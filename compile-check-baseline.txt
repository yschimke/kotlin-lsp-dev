# This list is currently EMPTY, and keeping it that way is the point.

# It used to hold 18 files. Two things emptied it:
#
#   1. The submodule is pinned at the release tag itself (kotlin-lsp/v<version>), not at a
#      later master commit. Sources and jars are then the same build, so there is no skew to
#      baseline. Always re-pin to the tag when bumping dist.properties.
#   2. compile-check.sh applies the kotlinx-serialization compiler plugin and puts the real
#      kotlinx-serialization-core jar ahead of the manifest-less copy embedded in
#      intellij.libraries.ktor.utils.jar. Without either, every `@Serializable` file reports
#      bogus errors that look exactly like drift.
#
# So a non-empty result here now means something real: either the pin drifted off the release
# tag, or the release genuinely changed an API the checkout uses. Investigate before appending
# -- an entry added to silence a failure hides exactly the signal this check exists to give.
